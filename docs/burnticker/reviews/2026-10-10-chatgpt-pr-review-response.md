# Response to the ChatGPT/Codex adversarial PR review (2026-10-10)

The report is published unedited in [2026-10-10-chatgpt-pr-review.md](2026-10-10-chatgpt-pr-review.md). It reviewed public commit
`58d43eae`, which is monorepo commit ≈ `1f717cb6`. We checked every finding against the code current on branch
`burnticker/codex-review-fixes`, cut from `0fccd14e` and merged with `fix/price-integrity-and-engine-correctness` up to `fff4dc04`.
Later commits may already have fixed a finding, so we did not take any finding as given. For each finding we wrote a focused regression
test first. For N1, N2, N4, N5, N6, N7 and C1 we reverted the source files and re-ran the tests, and the finding's core tests **failed
on the pre-fix code**. Some tests pass on both versions; they are kept as regression guards: the N1 verifier unit test, N7 "at or
before the launch baseline", C1 "flag on", and 10 of the 16 errata tests. N3's new tests import `burnProvenance`, which did not exist
before the fix. N3's evidence is instead the old `test/burntickerSdk.test.ts` fixture: it built a memo-only transaction and asserted
that the chain check passed. We then fixed the code and ran the full suite.

The regression tests are in `test/burntickerCodexReview.test.ts` (32 tests), except where the table names another file.
`test/burntickerPublicRepoSymlink.test.ts` (6) covers the export. `test/burntickerReviewErrata.test.ts` (16) covers the errata.

| **N7** (Medium): late-finalized events are permanently skipped behind the settlement cursor | **confirmed, fixed** | `N7 — …`: "binary: event A closes first but finalises after event B settled — A is still planned", "binary: a newly discovered event at the cursor's own timestamp with an earlier id is planned", "a reading at or before the launch baseline is never planned", "fixed-baseline scalar without carry…: a late day is planned on its own value", "ordered scalar (previousSettlement): a late period behind the cursor is NOT re-applied… carry preserved, an alert raised", "fetch window: while an event awaits finality the read window does not slide past it" | `5c60ff48` | Binary rules, and scalar rules against a fixed baseline with no carry, now use per-event identity after the immutable launch baseline. `programs/` were not edited.
