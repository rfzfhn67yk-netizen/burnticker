# burn_receipts — independent (blind) security review, 2026-10-09

Reviewer: Claude (Fable 5.1), read-only, no design docs read except README §5 (deployment facts).
Scope: `programs/burn-receipts/programs/burn_receipts/src/**`, `…/tests/**`, `src/lib/burnReceipts/**`.
Treated as claims to test: "SOL/tokens leave only via swap→burn; N-of-M ed25519 quorum; rules immutable; 48 h attester timelock; set never
below quorum; 25 SOL cap raise-only + sunset ≤ 365 d; no withdraw/sweep/close/mint/pause/update instruction."

Headline: **no path was found by which any key extracts SOL or tokens from the fee PDA, the vault or the config accounts** (checklist 2
PASS). The real exposure is economic and operational: (1) the buyback swap is a deterministic, publicly scheduled market buy whose only
sandwich defence is the TWAP tolerance, which is therefore a per-crank extraction budget (~14 % of each spend at the test config, ~89 %
if the guard is disabled, which `validate_rule` allows); (2) the fee-inflow side (LaunchLab/CPMM creator fees → fee PDA) is not
implemented consistently between this program and the keeper in the same repo, and one of the two legs strands fees; (3) several
irreversible-wedge states exist by design (no admin can rescue) and two of them can be entered by honest operation (missing
PlatformConfig after authority finalization; a legitimate reading outside `max_abs_delta`).

## 2. Per-checklist verdicts

### 1. Signers / ownership / PDAs / discriminators / mutability / remaining_accounts — **PASS**
- Every PDA is re-derived with stored bumps (`config.bump`, `config.fee_bump`, `reading.bump`, `platform.bump`); `initialize_token`/`initialize_platform` use canonical `bump` on `init`.
- `Account<T>` on every program account gives owner + discriminator checks; `SystemAccount` on the fee PDA; `Program<Token>` pins classic SPL Token; `address =` constraints pin sysvar, CPMM, memo, WSOL mint, `config.mint`, `config.cpmm_pool`.
- Third-party accounts: `PoolView/AmmConfigView/twap_sol_price_x32` check owner == `CPMM_PROGRAM_ID`, 8-byte discriminator and length before any field read (`cpmm.rs:65-70`); vaults/amm_config/observation are pinned to the pool's own fields (`crank_buyback.rs:96-99`); `cpmm_authority` is validated by Raydium's own seeds.
- Offsets verified against the pinned source (`fixtures/raydium-cp-swap@b3187ae5`): PoolState 637 B, `creator_fee_on`@389, `enable_creator_fee`@390, `creator_fees`@397/405, `status`@329 bit 2 = swap, `open_time`@373; AmmConfig `trade_fee_rate`@12, `creator_fee_rate`@108, 236 B; ObservationState 4 075 B, `observation_index`@9, observations@43 (40 B each), **`last_update_timestamp`@4043 is a real field** (not padding) and the code's bucket semantics comment is accurate.
- Writable sets are minimal and correct (`platform` read-only in crank; `mint` mut for burn). No instruction reads `remaining_accounts`.
- Signers: `initialize_token` requires payer + creator + **mint** (tested: `init_requires_the_mint_signature`); `initialize_platform` requires the upgrade authority against `ProgramData` (tested); admin/platform-authority paths compare the signer to the stored key; permissionless paths only need *a* signer (recorded in events).

### 2. Exit paths for SOL / tokens — **PASS** (with H-2 as the inflow caveat)
- SOL leaves the fee PDA only in `crank_buyback.rs:139-147` to `fee_wsol` (ATA constraint-checked, owner = fee PDA) and only by `spend ≤ pool_actual = fee − reserve + wsol`; post-condition `fee ≥ reserve` (`:149`) and the post-swap WSOL balance identity (`:175`).
- WSOL leaves `fee_wsol` only inside the CPMM CPI to the pool's own vault (`input_vault` key-checked); output lands in `fee_tokens` (ATA-checked) and **everything** in `fee_tokens` is burned (`:182-196`).
- Vault mode: the config PDA signs only `Burn` from its own ATA (`crank_vault.rs:53-64`).
- No `close`, no `realloc`, no `transfer` elsewhere, no `Option` payer tricks; ATA creation is client-side with the cranker as payer and can only create the canonical ATAs. Confirmed by tests `fee_pda_lamports_move_only_in_crank_buyback`, `program_token_accounts_cannot_be_moved_closed_or_reassigned`, `buyback_token_calls_are_only_sync_native_and_burn_from_the_program`, and the IDL instruction-list tests (Rust + TS).
- CPI targets are constants (`CPMM_PROGRAM_ID`, `MEMO_PROGRAM_ID`, `token::ID`, `system_program::ID`), not account keys.

### 3. CPMM swap CPI — **FAIL on economics (H-1), PASS on substitution**
- Pool/vault/program substitution: not possible (see 1). Policy-0 registration requires `pool_creator == fee PDA`; Raydium's permissionless `initialize` sets `pool_creator` from a **Signer** (`initialize.rs:24`), the permissioned path from an unchecked `creator` but behind a `Permission` PDA (`initialize_with_permission.rs:27,161`) — a look-alike pool cannot be manufactured (tested with mutated copies).
- `min_amount_out` is conservative versus Raydium's curve for both creator-fee placements (fee on input: `a(1−f)R_out/(R_in+a(1−f)) > (1−f)·ideal`; fee on output: `(1−f_c)(1−f_t) ≥ 1−f_t−f_c`), uses reserves net of protocol+fund+creator fees exactly like `vault_amount_without_fee`, and enforces `got ≥ min_out` again after the CPI.
- TWAP: cumulative integrates the **pre-swap** price (`swap_base_input.rs:203-207`), `t_end = max(last_update, t_new)` is right for the bucket semantics, Q32 units match. Same-block manipulation cannot enter the TWAP. **But** the tolerance is the sandwich budget and the window is walkable (H-1, L-7).
- Griefing: a > `max_dev` push makes the crank defer (`TwapDeviation`) only until the attacker unwinds or the window elapses; donating tokens to the vault only lowers the price (more burn); donating WSOL raises it and is caught by the guard. No permanent griefing found except via Raydium admin status (M-4).

### 4. Ed25519 introspection — **PASS** (M-3 on domain separation)
- Message format binds feed, date, value (fixed decimals), source hash, proof hash; **not** program id / mint / config (M-3) and not `prev_date` (L-1).
- Offsets: every triple must reference the ed25519 instruction itself (`u16::MAX` or its own index), slices are bounds-checked, and the program reads exactly the bytes the precompile verified (`attest.rs:78-82`; tested `ed25519_offsets_into_another_instruction_are_refused`). Instructions anywhere in the tx are scanned; a bad signature fails the whole tx under both pre- and post-`move_precompile_verification_to_svm` semantics because the tx is atomic.
- Duplicate attesters count once (bitmask), outsiders are ignored, quorum is `count_ones ≥ quorum` with `1 ≤ quorum ≤ count ≤ 5` (tested).
- Replay across dates: impossible (date in message + `StaleReading`/`ConflictingReading`); across tokens/deployments: possible (M-3).

### 5. Readings and arithmetic — **PASS** (M-2 on the plausibility wedge)
- Append-only (`reading.record_date != 0` short-circuit, same value no-op, different value refused; tested byte-for-byte), strictly increasing dates, future dates refused against `utc_date(clock)`, value ∈ (0, i64::MAX], non-zero source hash.
- `step`: i128 delta, u128 totals, checked ops, carry always `< unit`, CARRY_NONE never carries; floor division (units rounded down, remainder carried — correct direction).
- `buyback_spend`: floors `keep` ⇒ rounds **spend up** by ≤ 1 lamport and never exceeds `pool`; `pow_scaled_floor` products ≤ 1e36 < u128; `pool × keep_pow` ≤ 1.8e37. `min_amount_out`: `(2^64−1)^2 < 2^128`. All pinned by vectors shared with the TS mirror (34 TS tests pass).
- `settle_vault` consistent (shortfall is necessarily 0 when the allocation is reached). Overflow in vault planning is a config-dependent wedge (L-4).

### 6. Timelocks and governance — **PASS**
- Attester proposals: `eta = now + 48 h`, `apply` requires `now ≥ eta` (tested at `eta − 1` and `eta`); re-proposing resets the clock; cancel/renounce clear it; nothing applies after renounce. Quorum monotone (checked at propose and apply); set size ≥ quorum by `validate_attesters`. No indirect lowering path found. Full-set replacement is allowed (L-2).
- PlatformConfig: creation gated by `ProgramData.upgrade_authority_address == upgrade_authority` (tested with a stranger and the authority); raise-only (`>` at propose and apply), 48 h, sunset `(now, now+365 d]` fixed at init, `active_cap` strictly `now < sunset`; renounce freezes the cap at its current value. Events emitted on every state change (tested `every_state_change_emits_an_event`); the only gap is I-2.
- Renounce consequences: attester admin renounce + key loss ⇒ readings stop forever ⇒ fee SOL accumulates with no exit (accepted design; note in docs).

### 7. Initialization — **PASS**
- Mint keypair must sign; config PDA `init` ⇒ one config per mint ever (tested second init fails); creator/admin recorded; reserve funded to `≥ rent(0)`; `params_hash` reproducible (tested). Token-2022 mints are rejected at crank time (`Program<Token>`), not at init — a Token-2022 launch would be a dead config (informational; the mint does not exist yet at init so it cannot be checked there).

### 8. Vault mode — **PASS**
- Vault = config PDA's ATA (anyone may create, nobody but the program may debit); shortfall carried and repaid first (tested); allocation cap exhausts cleanly; `crank_no_units` only moves the cursor for `units == 0` readings that are next in line (tested ordering/idempotency).

### 9. Client — **PASS** with L-5, L-6
- Every send is simulated first (`simulateAndSend`), then sent with `skipPreflight` (acceptable since already simulated) and confirmed by polling; mainnet refused by label and by genesis hash unless `allowMainnet` (L-6).
- Signature packing matches web3.js's `Ed25519Program` byte-for-byte (TS test) and the Rust harness; multi-entry offsets resolve correctly; `0xffff` indices are what the program accepts.
- Memo formatter/parsers round-trip the on-chain strings for 2-decimal feeds (TS test + Rust memo tests + LiteSVM log assertions); decimals hard-coded (L-5).
- Secrets: `signAttestation` takes the 64-byte secret in memory, never logs it, never reads env/files; no key material in the IDL or constants.
- Instruction builders take account order/flags from the generated IDL; drift test against a fresh build exists and passed with the build I made.

### 10. DoS / liveness — **partial FAIL** (M-1, M-2, M-4, L-3, L-4, L-7)
- Not wedgeable by third parties through dust/rent (pre-funded PDAs are handled by Anchor's init path; donations to the fee PDA/ATAs are simply burned); the queue cannot be reordered or skipped; a failed crank is retried with recomputed amounts.
- Wedgeable by honest operation or external admins: missing PlatformConfig after finalisation (M-1), out-of-bound true reading (M-2), dead/disabled pool (M-4), frozen token account (L-3), vault overflow (L-4), over-long TWAP window on an active pool (L-7).

### 11. Upgrade authority / deployment (README §5) — see I-5
- The runbook is coherent (Squads 2-of-3 + 48 h, finalise with loader `SetAuthority` none). The ordering constraint "platform init **before** finalisation" is implicit and fatal if missed (M-1). The devnet/mainnet feature flag and `anchor keys sync` are the two silent-mismatch risks.
